## 五.6 已知 debt（实施过程中记录）

### sell fill `sold_cost_basis_usdc` / `realized_pnl_usdc` 暂为 None

- 位置：`replay-engine/src/live_driver.rs` `trade_log_to_paper_fill_event`
- 现状：sell fill 的 `sold_cost_basis_usdc` 与 `realized_pnl_usdc` 都返回 None
- 原因：`TradeLog`（`replay.rs:181-208`）只持有成交后账户状态，不持有成交前的 cost_basis 快照；要算 `sold_cost_basis_usdc = 卖出股数 × 卖前持仓平均成本` 需要 ack 处理前的 cost_basis 快照
- 影响：
  - **A 路 parity 不受影响**：A 路 shadow gate 比对的是 (obs / model / nav) 而不是 trades.jsonl realized PnL
  - **B 路 shadow 受影响**：sell 的 realized PnL 无法校验，但 NAV 比对仍然有效
  - **周聚合受影响**：`§4.5 sanity check（严格口径）= realized_pnl + final_unrealized_pnl ≈ nav_end - starting_cash` 在有 sell 时 realized 偏小，需要 NAV-derived `total_pnl = nav_end - starting_cash` 作为 ground truth
- 后续解决方向：
  - (a) 扩展 `PendingAck` / `TradeLog` 加 `pre_ack_cost_basis: f64` 字段（在 `process_scheduled_events` ExchangeArrival 阶段 snapshot 一次）
  - (b) 在 `LiveExecutionDriver` 内部维护 per-(market_id, outcome) cost basis snapshot，sell ack 时算 sold_cost_basis
- 跟踪：M6 主循环 / parity gate 通过后再决定是否实施扩展，当前不阻塞主线
