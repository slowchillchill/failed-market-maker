## P3. M2 feature-engine 特征生成 ─ 5 套串行（6–12 h）

**前置**（按 GPT 第四轮反馈 2 修正——与 P2 失败模式表述一致）：

**操作**（按 GPT 第五/十轮反馈修正——pipefail + 显式 RAYON_NUM_THREADS=20 防 cgroup v2 oversubscribe）：

⚠️ **GPU 服务器实测 quota = 25 vCPU + 90G RAM**（cpu.max = 2500000 100000）。但 affinity mask 显示 208 核——rayon 默认会起 208 worker thread，被 CFS 限流到 25 等效满载，**严重上下文切换浪费**。**必须显式 `RAYON_NUM_THREADS=20`**（留 5 vCPU 给系统 + Python overhead）。

```bash

  echo "===== [M2 X/5] feature-engine $dv $(date +%H:%M:%S) ====="
  RAYON_NUM_THREADS=20 cargo run --release --manifest-path poly-arb-ai/rust/Cargo.toml -p feature-engine -- \
    --dataset-version $dv --step-ms 250 --top-k 5 \
    --output-path model/feature-engine/out/features_250ms_${dv}.parquet \
    2>&1 | tee logs/m2_${dv}.log
  [ "${PIPESTATUS[0]}" = "0" ] || { echo "FAIL: feature-engine $dv"; exit 1; }

```

⚠️ **5 dv 必须串行**（不可并行）：单 dv 内 rayon 已用 20 vCPU 接近饱和；并行 5 dv = 100 vCPU 抢 25 quota → 100% CFS throttle 性能反而下降。

**进度监控**：feature-engine 用 stderr 打印 `[feature-engine] dataset=X step_ms=Y windows=N` 与单 window 进度；外层每个 dv 打印 `===== [M2 X/5] =====`。

**验收**（按 GPT 第五/六/七轮反馈修正——num_rows + schema + 覆盖率；只读必要列防 OOM；逐文件累加避免 concat 全表）：

```python
import pyarrow.parquet as pq
import glob
import os
import pandas as pd

REQUIRED_COLS = {"decision_ts_ms", "market_id", "dataset_version", "window_id",
                 "y_cls", "y_ev_up", "y_ev_down"}
COVERAGE_COLS = ["window_id", "market_id"]   # 只读这两列做覆盖率，避免 OOM

for dv in ["data-v1", "data-v2", "data-v3", "data-v4", "data-v5"]:
    agg_path = f"model/feature-engine/out/features_250ms_{dv}.parquet"
    pw_paths = sorted(glob.glob(f"model/feature-engine/out/features_250ms_{dv}_*.parquet"))
    if os.path.exists(agg_path):
        paths = [agg_path]
        mode = "aggregate"
    elif pw_paths:
        paths = pw_paths
        mode = f"per-window x{len(paths)}"
    else:
        raise FileNotFoundError(f"{dv}: 既无 aggregate 也无 per-window parquet")

    # 1) schema 验证只读 1 行（不耗内存）
    schema = pq.read_schema(paths[0])
    cols = set(schema.names)
    assert REQUIRED_COLS.issubset(cols), f"{dv} missing cols: {REQUIRED_COLS - cols}"

    # 2) 行数 + 覆盖率：只读必要列，逐文件累加 set 而不 concat 全表
    feat_pairs: set = set()
    total_rows = 0
    for p in paths:
        t = pq.read_table(p, columns=COVERAGE_COLS)
        total_rows += t.num_rows
        feat_pairs.update(zip(t.column("window_id").to_pylist(),
                              t.column("market_id").to_pylist()))
        del t
    assert total_rows > 0, f"{dv} empty"

    # 3) 与 manifest+labels valid set 对比
    md = pq.read_table(f"poly-arb-ai/data-pipeline/out/{dv}/manifest.parquet",
                      columns=["window_id","market_id","is_valid"]).to_pandas()
    ld = pq.read_table(f"poly-arb-ai/data-pipeline/out/{dv}/labels.parquet",
                      columns=["window_id","market_id","label_status"]).to_pandas()
    valid = md.merge(ld, on=["window_id","market_id"], how="inner")
    valid = valid[(valid["is_valid"]) & (valid["label_status"] == "valid")]
    expected_pairs = set(zip(valid["window_id"], valid["market_id"]))
    coverage = len(feat_pairs & expected_pairs) / max(len(expected_pairs), 1)
    print(f"{dv} [{mode}]: rows={total_rows:,} markets={len(feat_pairs)} "
          f"coverage={coverage:.3f} (expected={len(expected_pairs)})")
    assert coverage >= 0.95, f"{dv} feature coverage {coverage:.3f} < 0.95 — 历史 M2 曾出现覆盖缺口，停下定位"
```

**Split 防泄漏 sanity check**（按 GPT 第五/七轮反馈修正——同 ts 跨 split 改为 hard fail，避免复制粘贴时被 WARN 一笔带过）：

```python
import json
split = json.load(open("poly-arb-ai/training/split/split_info.v6expanded.json"))
ALLOW_TS_OVERLAP = False  # 如经人工确认特定 ts 重叠是无害的（例如 ts 精度噪声），改为 True

seen_ts = {}
seen_window = {}
ts_leaks = []
for split_name in ["train", "val", "test"]:
    for w in split[split_name]:
        ts_key = w["window_start_ts_ms"]
        wid_key = (w["dataset_version"], w["window_id"])
        # (1) 同一 (dv, window_id) 必须只在一个 split — hard fail
        if wid_key in seen_window:
            assert seen_window[wid_key] == split_name, \
                f"LEAK: {wid_key} 跨 {seen_window[wid_key]}/{split_name}"
        seen_window[wid_key] = split_name
        # (2) 同一 window_start_ts_ms 跨 split = 时间泄漏（跨 dv 但同时刻信息同时进入 train+val/test）
        if ts_key in seen_ts and seen_ts[ts_key] != split_name:
            ts_leaks.append((ts_key, seen_ts[ts_key], split_name, w['dataset_version']))
        seen_ts[ts_key] = split_name

if ts_leaks:
    for ts, s1, s2, dv in ts_leaks[:10]:
        print(f"TS_LEAK: ts={ts} 同时在 {s1} 与 {s2} (dv={dv})")
    print(f"... total {len(ts_leaks)} ts leaks")
    if not ALLOW_TS_OVERLAP:
```

## P8. M5 评估 ─ 双路线（K2-C signal route + M5 agent route）（3–6 h）

**前置**：P7 至少 Oracle-BC ONNX 已导出。

**关键决策（按 GPT 第二/三轮反馈修正）**：
- signal route 用的是 ONNX 的 `signal head + size head + limit head`（policy/order_type 被 strategy=signal/force-order-type 覆盖，risk 被 override-risk-score 覆盖）。**不同 ONNX 在 signal route 下结果不同**，因为 size/limit head 来自不同训练。
- 历史 K2-C 锚点是 `j1_b_from_m3/agent_model_m5.onnx`（trained ONNX from BC，依赖环境说明.md:721），不是 collection ONNX。
- **K2-C signal route 至少跑两组**：collection ONNX + BC ONNX；优先看 BC ONNX 与历史 +66 的对比。
- agent route 用 ONNX 的全部 head（用于诊断 IQL/BC policy 是否塌缩）。

|------|------|----------|---------|
| **K2-C signal route** | 复现冻结候选 +66 PnL（历史口径） | `--strategy signal --signal-threshold 0.58 --force-order-type limit --override-risk-score 1.0` | `m3_v6_collection_signal`（baseline）, `m5_v6_bc_signal`（**主候选，对应历史 K2-C**）|
