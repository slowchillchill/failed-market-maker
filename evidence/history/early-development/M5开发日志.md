### RewardCalculator

实现 4 个组件：
1. **不对称 ΔNAV**：`α_loss=1.5` 放大被动亏损，主动纠错不放大
2. **Turnover penalty**：`λ_turn=0.0005` × turnover_notional
3. **Drawdown penalty**：`λ_dd=0.5` × 增量回撤
4. **Idle penalty**：`λ_idle=0.0001`（空仓 + 非冷启动时）

### TransitionStrategy

- 包装 AgentStrategy + RewardCalculator
- 每个 decision tick 生成一个 TickStreamRow（含 warm-up）
- Ready tick 的 reward **延迟一个 tick 写回**（区间 `[tick_k, tick_{k+1})` 的 reward 写到 tick_k）
- `flush_final_transition(final_nav)` 补写 terminal reward + `done=true`
- `on_fill_ack` 累积 turnover（买入用 `amount_usdc`，卖出用 `proceeds_usdc`）

### Tick Stream Parquet Schema

96 列：6 索引 + 76 特征(feat_0..feat_75) + 4 动作(nullable) + 1 reward(nullable) + 1 done + 8 诊断

## S3: IQL 训练实现 ✅

### 新建文件

| 文件 | 用途 |
|------|------|
| `training/transition_dataset.py` | TransitionDataset（从 tick_stream 重建 [seq_len, 76] 观测） |
| `training/iql.py` | FactoredQNetwork + ValueNetwork + IQLTrainer |
| `training/train_iql.py` | 训练 CLI 脚本 |
| `training/test_iql.py` | 19 个测试 |

### TransitionDataset

- 按 `(dataset_version, window_id)` 分组为 episode
- 从 `buffer_ready=True` 行建立 transition 索引
- `__getitem__` 返回 `(obs_t, actions, reward, obs_next, done)`
- `obs_next` 在 done=True 时返回全零张量（D8）
- 不跨 episode 回看（D5）
- `time_ordered_split()` 按 `(window_start_ts_ms, dataset_version, window_id)` 排序切分（D9）
- `compute_feature_stats()` 从 buffer_ready=True 行计算 mean/std

### IQL 核心

- **FactoredQNetwork**：4 个独立 QHead（policy/size/order_type/limit_level）
- **ValueNetwork**：V(s) → scalar
- **IQLTrainer**：
  1. Q update：`Q(s,a) → MSE(r + γ(1-done) × V_target(s_next))`，4 头求和后取 MSE
  2. V update：expectile regression `L_τ(V(s) - min(Q1_total, Q2_total))`，τ=0.7
  3. Policy update：advantage-weighted regression `-log π(a|s) × exp(A/β)`，β=3.0
  4. EMA target update：`θ_target ← (1-τ_ema)θ_target + τ_ema × θ`
- **骨干冻结**：IQLTrainer 初始化时自动冻结 normalizer/branches/transformer/signal_head
- **RiskHead 排除**：不纳入 optimizer、不作为 Q-head

### train_iql.py

## 已知问题与风险

### 1. 采集性能

单 window（246 markets）全量采集约需 **1.5-2 小时**（release 模式，CPU）。三个 dataset 总计约 10 个 window，预计 **15-20 小时**。ONNX 推理是瓶颈（每 tick 一次 forward pass，约 240×76 浮点输入）。

**缓解**：可在 GPU 服务器上并行采集多个 dataset，或用 `--limit-markets` 子采样。

### 2. IQL 训练稳定性（未验证）

Settlement tick 的 reward 可能达 ±$30（结算 PnL），与普通 tick 的 ±$0.01 差异巨大。是否需要 reward clipping 需在实际训练中验证。

**缓解**：计划中预留了 reward clip [-5, +5] 备选方案。

### 3. 确定性行为策略探索不足

Collection 模式使用随机初始化权重 + argmax 解码，行为策略接近确定性。如果探索不够，IQL 训练效果可能受限。

**缓解**：计划中预留了 ε-greedy(ε=0.1) 备选方案。

### 4. from_pretrained 的 d_model 冲突

`PolyArbAgentModel.from_pretrained()` 自动从 checkpoint 推断 `d_model`，如果 kwargs 中也传了 `d_model` 会报 `TypeError: got multiple values`。调用方**不应**同时传 `d_model`。

### 5. Parquet 行数预估

当前验证用 3 markets 产出 3600 rows。全量 data-v1（8 windows × ~250 markets × ~1200 ticks）预计 ~2.4M rows，3 个 dataset 总计 ~7-8M rows。单个 parquet 文件大小预计 2-4 GB。

S4 全量采集 + m5_run1/m5_run2 训练完成后，首次 evaluate 发现 agent 在 held-out 上严重亏损。进入一系列诊断 + 修补循环，每轮都在 `dev-docs/M5开发日志.md` 之外以 task #29-#47 形式跟踪。这里做一次**事后汇总**，避免阅读任务列表才能还原历史。

### Phase 11.1 — 余额校验 + size_mapping 语义修复（task #29）

**症状**：m5_run2 agent 在 test windows 上 mean_return ≈ -5%。

**根因**：
1. `arbiter.rs` size_mapping 用的是"绝对股数 = {5, 15, 30}"而不是 `% NAV`，导致高价 market 下一笔 medium 单就 ≈ 50% 资金。
2. 下单前没有现金余额校验，ESM 会反复下失败订单。
3. Collection 时 `argmax` 完全塌缩到 `OpenUp/small`。

**修复**：
- 该阶段围绕仓位语义与现金约束做了修补；当前仓库实现最终以目标股数档 `[5, 15, 30]` + `arbiter::apply_cash_cap()` 的现金夹紧为准，不再把 `% NAV` 口径当作现行契约。
- 买侧目标增仓会在策略层先经过现金可承受范围夹紧，避免继续朝超额买入目标下单。
- `transition_strategy.rs`：采集时从 `argmax` 切换为 `softmax 采样`（Phase 11.2 进一步强化）。

### Phase 11.8-H — 三大独立诊断（task #47）

**动机**：用户提醒 Phase 11.8-G 的"没有信号"是循环推理——"winner/loser"本身是用采集策略自己的 PnL 定义的。需要**不依赖 collection policy** 的诊断。

新建 `/tmp/diag_phase_11_8_h.py`，用 `tick_stream/v{1,2,3}.parquet` 和 `data-pipeline/out/data-v*/labels.parquet` 做三件事：

1. **Oracle 上限** — 如果 t=0 知道 `label_up`，在 best_ask 买入 100 USDC 赢家：
   - **每笔平均 +94%**，100% positive。
   - 说明数据本身的"上限利润"非常大。
2. **M3 信号头方向精度（proxy）** — 用 collection 探索期间 action_policy 的 OpenUp/OpenDown 出现率对 label_up 做准确率：
   - **54.1%**，高于基线 48.9%，差 ~5.2pp。
   - 含 fee 后 EV ≈ +4.95% / 笔（远高于 reward_clip=1 USDC 的幅度）。
3. **E[reward | action, label_up]** — 按 (action, label) 统计条件均值：
   - 方向正确 vs 错误的期望差 **几乎被裁平**。
   - OpenUp 在 label_up=True / False 两边 mean reward 非常接近。

**结论反转**：数据**有强信号**，但 `reward_clip=Some(1.0)` 把 ±20 USDC 的结算差额全斩断到 ±1，IQL 的 Q-head 根本看不见方向性差异。这就是为什么 policy loss 卡在均匀熵上。

### Phase 11.8-I — Reward 纯 ΔNAV 重建（task #48）

**方案**：不重新 rollout 采集（Rust 很慢），直接在 Python 里把 tick_stream 的 reward 列重算：
- `new_reward[k] = nav[k+1] - nav[k]`（按 window 内 `shift(-1)`）
- 所有 penalty 关闭（alpha_loss=1.0, lambda_turn/dd/idle=0, reward_clip=None）
- warmup + 每个 market 首 ready tick 保持 NaN
- window 末 tick shift-NaN 退回原值（terminal fallback）

脚本：`/tmp/rebuild_reward_minimal.py`，产物：`tick_stream/v{1,2,3}_reward_minimal.parquet`。

统计对比：

| | 旧（clipped） | 新（纯 ΔNAV） |
|---|---|---|
| min/max | -1.00 / +1.00 | -11.85 / +13.34 |
| |reward| > 1 比例 | 0% | ~0.8% |
| label_up=True 的 per-episode 总 reward | -5.20 | **+0.70（符号反转）** |

**m5_run5** 用新数据重训：
- policy_loss 从 5.25 降到 4.62 然后**又卡住**（m5_run4b 是 4.69 直接冻结）。
- V̄ 从 -0.23 降到 -0.31，下降但极慢。
- `/tmp/probe_policy_dist.py` 在 2000 个真实 transition 上再跑 argmax → **100% Hold**；mean P(Hold)=0.571，其它 5 个动作平均 ~0.086。
- Logit std 0.13–0.25，仍然近均匀分布。

### 阶段性结论

1. **数据有信号**（Oracle +94%，M3 方向精度 54.1%）。
2. **Reward 已修复**（±13 范围，label 对齐）。
3. **IQL 仍然塌缩到 Hold**。

这三件事同时成立，意味着问题**不是数据/reward，而是 offline RL 范式 + 长时稀疏奖励 + dominant-Hold 动作分布的结构性组合**：
- γ=0.9995，settlement 在 ~1200 tick 之后，`γ^1200 ≈ 0.549` 衰减。
- Hold 占 58% → Q(s, Hold) 被学得最精细 → 系统性偏置。
- β=3.0，Q 差异 ≈ 0.2 → AWR 权重比 ≈ 1.07，几乎等于行为克隆。
- 行为本身是"Hold 众数"，policy 学的就是 Hold。

**决策**：放弃纯 offline IQL 作为 M5 唯一范式，转向 **Oracle-guided BC → Hybrid BC+IQL** 的路径。具体诊断与最终收口口径见 `dev-docs/M5待解决问题.md`。

### Phase 11.8-K2-C（2026-04-15，full-range 扫描 + `val` 8 窗口失效定位）

- frozen split 口径保持不变：`source://legacy/poly-arb-ai/training/checkpoints/m5_run_bc_diag/split_info.frozen.json`，`train/val/test = 39/8/10` 个 window；其中 `train = data-v1(2) + data-v2(20) + data-v3(17)`，`val/test` 都只来自更晚的 `data-v3`。

  - `train`：`+3282.0262` vs `+9.3774`
  - `val`：`-95.1558` vs `+0.6233`
  - `test`：`+66.0951` vs `-26.1318`
  - `full`：`+3252.9655` vs `-16.1311`（净优势 `+3269.0966`）

  - 最差的 miss 集中在错误方向、入场价约 `0.55~0.63` 的单市场，单笔可亏 `~8` 到 `9.45` USDC。
