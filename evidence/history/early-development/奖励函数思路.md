# M5 奖励函数设计构思

> 经多轮审核确认，作为 M5 实施规范。

---

## 1. 设计原则

1. **唯一 NAV 口径**：奖励以 `NAV_after_fee` 的变化为核心，slippage 已在 fill price 中体现，fee/rebate 已在 cash 中体现，不重复扣减。
2. **不对称盈亏（区分主动/被动）**：被动承受亏损（持仓缩水）放大惩罚，鼓励快速止损；主动纠错（止损卖出、减仓）不放大，鼓励果断行动。盈利始终全额计入。
3. **长期视野通过 observation 实现**：不在 reward 中编码长期绩效信号（避免"躺平"激励），而是将近期结算 PnL 历史作为特征输入 observation，让模型自主学到跨 market 的资金管理。
4. **惩罚躺平**：空仓不交易有成本（idle penalty），迫使模型积极寻找交易机会。
5. **尊重业务规则**：双侧持仓是合法套利策略（`price_up + price_down < 1` 时持有到结算可盈利），不应被惩罚。同一 market 内允许双侧多次交易。
6. **最小干预**：仓位大小已由 SizeHead + HardRiskGuard 约束，fee 已是天然交易摩擦。惩罚项只做必要的行为塑造，不过度干预。
7. **与已有系统对齐**：NavSnapshot（DecisionTick 等间距 250ms）已在 M4 实现，奖励计算直接复用。
8. **可调优先于精确**：所有系数作为超参数暴露，首版取保守值，后续通过回放验证调整。

---

## 2. 核心公式

```
# 不对称 ΔNAV（区分主动纠错 vs 被动承受）
if ΔNAV(t) >= 0:
    reward_nav = ΔNAV(t)                        # 盈利：全额计入
elif has_trade_this_tick:
    reward_nav = ΔNAV(t)                        # 主动纠错（止损/减仓）：不放大
else:
    reward_nav = α_loss × ΔNAV(t)               # 被动承受（持仓缩水）：放大

# 惩罚项
turn_penalty = λ_turn × turnover_notional(t)
dd_penalty   = λ_dd × max(0, Δdrawdown(t))
idle_penalty = λ_idle if (空仓 and 非冷启动) else 0

# 最终 reward
reward_t = reward_nav - turn_penalty - dd_penalty - idle_penalty
```

所有项均以 **USDC 绝对值** 计算（初始 NAV = $100 USDC）。

## 3. 各项定义

### 3.1 不对称 ΔNAV：主信号（区分主动/被动亏损）

```
ΔNAV(t) = NAV_after_fee(t) - NAV_after_fee(t-1)

if ΔNAV(t) >= 0:
    reward_nav = ΔNAV(t)                   # 盈利：全额计入
elif has_trade_this_tick:
    reward_nav = ΔNAV(t)                   # 有交易（主动纠错）：不放大
else:
    reward_nav = α_loss × ΔNAV(t)          # 无交易（被动承受）：放大
```

- NAV = cash + inventory_mark_to_market（按可见 Polymarket 盘口保守立即平仓价值估值，复用 `AccountState::nav()`）
- **α_loss = 1.5**：被动亏损 $1 等价于 reward = -$1.50

**为什么区分主动/被动**：

BTC UP/DOWN 5MIN 市场时间窗口窄、波动大、resolve price 不会离 price to beat 太远，经常发生反转。如果 α_loss 对所有亏损一视同仁，止损卖出的那个 tick 会承受最大的负 reward（实现亏损集中在一个 tick），而扛着不动每个 tick 只有微小的 mark-to-market 负 reward。模型会学到"买错就不动"——这与正确的风险管理完全相反。

区分后的效果：
- **止损 1 tick**：ΔNAV = -$0.80，有交易 → reward = -$0.80（不放大）
- **扛着 20 ticks**：ΔNAV = -$0.05/tick，无交易 → reward = 1.5 × (-$0.05) = -$0.075/tick，累积 = -$1.50
- 扛 20 ticks（-$1.50）已比立即止损（-$0.80）更差 → 模型学到**早止损优于慢止损**
- 止损后反手买对侧且赢了 → 后续 tick 全是正 ΔNAV（reward 系数 1.0）→ 强化纠错行为

**其他说明**：
- **含结算**：market 最后一个 tick 的 ΔNAV 包含结算兑付跳变。二元期权的本质就是"赌 settlement"，模型需要学会何时该承担结算风险、何时该提前退出
- **首个 tick**：NAV(t-1) = 上一个 decision tick 的 NAV（跨 market 连续）。Session 的第一个 tick，NAV(t-1) = initial_cash
- **冷启动 tick**：HardRiskGuard 禁止交易，ΔNAV ≈ 0（仅盘口 mark-to-market 微变），不收 idle penalty（系统禁止，非模型选择）

**量级验证**：
- 普通 tick ΔNAV：±$0.01~$0.50
- 结算 tick ΔNAV：±$5~$30（取决于持仓大小和方向正确性）
- 被动亏损放大后：结算扛亏 -$20 → reward = -$30，盈利 +$20 → reward = +$20
- 主动止损 -$5 → reward = -$5（不放大，鼓励行动）

### 3.2 Turnover penalty：轻度抑制无意义交易

```
turnover(t) = Σ |filled_shares_i × fill_price_i|    （本 tick 所有成交的绝对 notional 之和）
```

- 只在**实际成交**时计费（挂单未成交不计）
- Fee ~0.9%（p=0.50）已是强力天然摩擦；此项仅作为微量附加，让模型内化"每笔交易有隐性成本"（执行不确定性、adverse selection 等 fee 未覆盖的因素）
- 系数设得足够低，不会抑制有 edge 的高频交易或正确的纠错行为

**默认值**：`λ_turn = 0.0005`（notional 的 0.05%）

**量级验证**：
- 典型交易 15 shares × $0.50 = $7.50 notional
- 惩罚 = 0.0005 × 7.50 = $0.00375
- 对比 taker fee = $0.0675 → 惩罚仅为 fee 的 5.6%，不会抑制有 edge 的交易
- 止损 + 反手两笔交易的 turnover penalty 合计 ≈ $0.007 → 对比纠错收益 $13+ 完全可忽略

**高频交易场景验证**：
- 一个 market 内 150 笔交易（每笔 15 shares × $0.50）
- 总 turnover penalty = 0.0005 × 150 × 7.50 = $0.56
- 总 taker fee = 150 × $0.0675 = $10.13
- Turnover penalty 仅占总摩擦的 5.2% → 不构成高频交易障碍

### 3.3 Drawdown penalty：抑制过度冒险

```
Δdrawdown(t) = max(0, drawdown(t) - drawdown(t-1))
drawdown(t) = max(0, peak_nav(t) - NAV(t)) / peak_nav(t)
peak_nav(t) = max(NAV(0), NAV(1), ..., NAV(t))
```

- **仅对增量回撤收费**：NAV 从 $100 跌到 $95 只在**跌穿新低**的那些 tick 产生惩罚，持续在 $95 横盘不重复收费
- **不与 ΔNAV 双重计费**：ΔNAV 已经惩罚了亏损本身（且被动亏损通过 α_loss 放大了）；此项额外惩罚**创新低**行为，使模型偏好控制波动率
- Peak NAV 在 session 内持续跟踪（不按 market 重置——与 evaluation.rs 一致）

**默认值**：`λ_dd = 0.5`

**量级验证**：
- NAV 从 $100 跌到 $99（1% 新增回撤）
- 惩罚 = 0.5 × 0.01 = $0.005
- 对比被动 ΔNAV 的 α_loss 放大后 reward = -$1.50 → drawdown penalty 仅为 0.3%，方向一致但不喧宾夺主

### 3.4 Inventory penalty：已取消

不设置 inventory penalty。理由：

1. **双侧持仓是合法套利**：Polymarket 二元市场中，`price_up + price_down < 1` 时同时买入双侧持有到结算可盈利。惩罚总持仓会错误地抑制这种正当策略
2. **仓位已有充分约束**：SizeHead（5/15/30 shares）和 HardRiskGuard（max_position_per_leg=50、drawdown limit、force close）已从多个角度限制仓位
3. **Fee 是天然持仓成本**：建仓需支付 fee，这已经是"仓位越大成本越高"的自然信号
4. **ΔNAV 已含持仓风险**：mark-to-market 波动直接体现在 per-tick ΔNAV 中，且被动亏损端有 α_loss 放大

### 3.5 Idle penalty：惩罚躺平不交易

```
if up_shares == 0 and down_shares == 0 and not cold_start:
    idle_penalty = λ_idle
else:
    idle_penalty = 0
```

- **空仓 + 非冷启动 → 每 tick 收取固定惩罚**
- 有持仓（无论赚亏）→ 不收取（持仓的风险/收益由 ΔNAV 处理）
- 冷启动 tick → 不收取（系统禁止交易，非模型选择）
- 逻辑：资金闲置有机会成本，模型应该积极寻找交易机会

**默认值**：`λ_idle = 0.0001`（$0.0001 / tick）

**量级验证**：
- 全程空仓一个 market（1200 ticks）：惩罚 = $0.12
- 对比 M3 验证的 top10_ev ≈ +$0.245/笔 → 错过一个好机会的成本约 $0.10~$0.25，idle penalty 在同一量级
- 全程空仓 288 个 market（24 小时）：惩罚 = $34.56（占 NAV 34%）→ 非常强的"不许躺平"信号
- 持仓一半时间、空仓一半时间：惩罚 = $17.28 → 仍然显著
- 单 tick 的 $0.0001 足够小，不会逼模型在盘口极差时强行开仓

## 4. 默认超参数

| 参数 | 默认值 | 含义 | 调优方向 |
|------|--------|------|----------|
| `α_loss` | 1.5 | 被动亏损放大倍率 | ↑ 更厌恶被动扛亏，↓ 对称化 |
| `λ_turn` | 0.0005 | 每 $1 notional 的交易摩擦 | ↑ 减少交易频率，↓ 允许更多交易 |
| `λ_dd` | 0.5 | 增量回撤惩罚倍率 | ↑ 更保守，↓ 容忍更大回撤 |
| `λ_idle` | 0.0001 | 空仓时每 tick 的机会成本 | ↑ 更激进逼迫入场，↓ 容忍空仓等待 |
| `γ` | 0.9995 | 折扣因子 | 有效视野 ~2000 ticks ≈ 2 个 market |

### 折扣因子选择依据

- γ=0.9995 → 有效视野 1/(1-γ) = 2000 ticks ≈ 500 秒 ≈ 约 2 个 5 分钟 market
- 配合 observation 中的历史 PnL 特征使用：γ 提供中期视野（2 个 market），observation 特征提供更长期信号（6 个 market / 30 分钟）
- 相比 γ=0.999（仅 1 个 market），γ=0.9995 让模型更关注下一个 market 的开局——例如在当前 market 末尾保留资金用于下一个 market

## 5. 长期信号：通过 Observation 传递

### 5.1 设计理由

**不在 reward 中编码长期绩效信号**（如 session bonus），因为：
- 任何与"当前 NAV 水平"挂钩的 bonus 都会引入"躺平"激励——不交易也能持续收到正 bonus
- Session bonus 把"你有多少钱"编码进 reward，而非"你的决策好不好"
- 前期盈利后 bonus 导致后期过度保守，与"持续积极交易"的目标矛盾

**正确做法**：将长期绩效信息放入 observation，让模型自主学到跨 market 的资金管理策略。

### 5.2 新增 Observation 特征

在原有 6 个 agent state 列之外，再增加 3 个滚动结算 PnL 特征 + 2 个 session 级特征：

| 特征 | 计算方式 | 窗口 | 作用 |
|------|----------|------|------|
| `settled_pnl_last_1` | 最近 1 个已结算 market 的 PnL / session_initial_nav | 5 分钟 | 短期：刚发生了什么 |
| `settled_pnl_last_3` | 最近 3 个已结算 market 的累积 PnL / session_initial_nav | 15 分钟 | 中期：最近趋势 |
| `settled_pnl_last_6` | 最近 6 个已结算 market 的累积 PnL / session_initial_nav | 30 分钟 | 较长期：30 分钟趋势 |
| `session_return` | (current_nav - session_initial_nav) / session_initial_nav | 全 session | 全局盈亏状态 |
| `rolling_drawdown` | 当前 session drawdown（peak_nav 口径） | 全 session | 当前风险水平 |

**FEATURE_COLS 变化**：65（M4 原始）+ 6（agent state）+ 5（长期信号）= **76 列**

多粒度结算 PnL 的作用：
- `last_1` 大亏但 `last_6` 为正 → 单次失手，不需恐慌
- `last_1`、`last_3`、`last_6` 全部为负 → 持续下行，应该保守
- 模型自主学到这些模式，不需要 reward 硬编码

## 6. Episode 与 Transition 结构

### 6.1 Episode 定义

- **一个 episode = 一个 window**（含多个 market）
- `done=True` 仅在 window 结束时
- Market 结算是 episode 内的"中间终端事件"——最后一个 tick 的 ΔNAV 包含结算 PnL，但 episode 继续到下一个 market
- feature_buffer 跨 market 保留（与 M4 strategy.rs 一致）
- risk_state 按 market 重置（与 M4 strategy.rs 一致）

### 6.2 单条 Transition

```
(obs_t, action_t, reward_t, obs_{t+1}, done_t, info_t)
```

| 字段 | 类型 | 来源 |
|------|------|------|
| `obs_t` | `[seq_len, F]` float32 | feature_buffer 当前窗口（F=76） |
| `action_t` | `(policy, size, order_type, limit_level)` | 模型输出的 4 个离散头 argmax |
| `reward_t` | float32 | 本文公式计算 |
| `obs_{t+1}` | `[seq_len, F]` float32 | 下一个 decision tick 的 feature_buffer |
| `done_t` | bool | window 结束 |
| `info_t` | dict | market_id, ts_ms, nav, cash, up_shares, down_shares, has_trade, is_settlement |

### 6.3 Action 编码

M4 的 4 个离散头构成 **factored action space**：

| Head | 维度 | 值域 |
|------|------|------|
| PolicyHead | 6 | hold/open_up/open_down/reduce/close/flip |
| SizeHead | 3 | small/medium/large |
| OrderTypeHead | 2 | market/limit |
| LimitPriceLevelHead | 5 | join_best/improve_1/2/passive_1/2 |

**IQL 处理方式**：每个 head 独立的 Q 网络 + 独立 argmax，无需展开为 180 维联合空间。这与 M4 的 factored 输出结构天然对齐。

### 6.4 Observation 扩展（65 → 76）

| 区间 | 列数 | 内容 |
|------|------|------|
| 1~65 | 65 | M4 原始 FEATURE_COLS（Polymarket / Binance / BLB / Chainlink / Time） |
| 66~71 | 6 | Agent state（up_shares / down_shares / up_value / down_value / position_value / floating_pnl） |
| 72~76 | 5 | 长期信号（settled_pnl_last_1 / last_3 / last_6 / session_return / rolling_drawdown） |

## 7. 行为策略（Behavioral Policy）与数据采集

### 7.1 数据质量考量

M4 agent 的动作头是**随机初始化**的，行为接近随机策略。这对离线 RL 意味着：

- **优势**：探索覆盖好，不会遗漏动作空间的某个角落
- **劣势**：大部分 transition 是 (Hold, reward≈0) 或无意义随机交易
- **IQL 的适用性**：IQL 通过 expectile regression 提取数据中的"best actions"，对低质量行为策略鲁棒

### 7.2 采集策略建议

1. **基线数据集**：用 M4 random agent 回放全部 training windows → 大量 transition（覆盖好但质量低）
2. **增强数据集**（可选，M5 实施时评估是否需要）：
   - 用 M3 SignalHead 构造简单启发式策略（如 `P_up > 0.6 → buy Up market small`）
   - 这提供了一些"有意义交易"的 transition，提升数据中正收益轨迹的比例
3. **多策略混合**：将基线 + 增强数据合并，提高样本多样性

### 7.3 数据规模估算

- 每个 market ≈ 1200 decision ticks
- data-v1: 288 markets → ~345K transitions
- data-v1+v2+v3: ~2400 markets → ~2.9M transitions
- 每条 transition 约 76×240×4 bytes (obs) × 2 + action(4 bytes) + reward(4) + done(1) + info → ~146KB
- 总量：2.9M × 146KB ≈ 420GB（如果存完整 obs_seq）
- **优化**：obs_seq 不重复存储，改为存 feature index + 从 parquet 按需切片重建 → 每条 ~100 bytes → 总量 ~300MB

## 8. 关键设计决策

### D1. 结算 ΔNAV 不做平滑

**选择**：结算 tick 的 ΔNAV 包含完整结算 PnL（可能 ±$30）
**替代**：将结算 PnL 平摊到 market 内所有 tick
**理由**：二元期权的经济本质就是"赌 settlement"。平滑会掩盖"持有到结算"决策的真实 risk/reward。模型需要学到：持有方向正确时获大 reward，错误时受大 penalty。

### D2. 取消 inventory penalty

**选择**：不惩罚持仓
**替代**：gross/net inventory penalty
**理由**：双侧持仓是 Polymarket 二元市场的合法套利策略（`A+B<1` 时确定性盈利）。仓位已由 SizeHead + HardRiskGuard 多重约束。Fee + mark-to-market ΔNAV 已是充分的持仓信号。

### D3. 增量回撤（非累积回撤）

**选择**：只在创新低时收 penalty
**替代**：每 tick 按当前 drawdown 百分比收 penalty
**理由**：累积 drawdown penalty 会在 NAV 低谷时持续惩罚 hold（即使 hold 是最优策略），导致模型在回撤后过度抛售。增量回撤只惩罚"继续亏损"的行为。

### D4. 区分主动纠错 vs 被动承受

**选择**：α_loss 仅作用于无交易 tick 的亏损
**替代**：α_loss 对所有亏损一视同仁
**理由**：BTC UP/DOWN 5MIN 市场波动大、频繁反转。不区分主动/被动会导致"买错不动"——止损 tick 的集中实现亏损被放大，而扛着每 tick 的微小 mark-to-market 亏损不被放大，模型学到不止损。区分后，被动扛亏累积惩罚 > 主动止损，模型学到"早止损优于慢止损"。

### D5. 长期信号通过 observation（非 reward）

**选择**：在 observation 中增加滚动结算 PnL + session 级特征
**替代**：在 reward 中加 session bonus
**理由**：任何与"当前 NAV 水平"挂钩的 reward bonus 都会引入"躺平"激励——前期盈利后不交易就能持续收到正 bonus。正确做法是让模型通过 observation 感知长期状态，自主学到"连亏后保守、连赢后继续"。

### D6. Idle penalty（惩罚空仓躺平）

**选择**：空仓非冷启动时每 tick 收固定惩罚
**替代**：空仓 reward = 0（不惩罚也不奖励）
**理由**：reward = 0 使躺平成为无风险 default。资金闲置有真实的机会成本——BTC 5MIN 市场每个 market 都有潜在 edge，不参与就是错过。λ_idle = 0.0001 足够小（单 tick $0.0001），不会逼模型在极差行情强行开仓，但 24 小时累积 $34 的惩罚足以阻止长期躺平。

### D7. Factored Q-learning（非 joint action space）

**选择**：4 个 head 各自独立 Q → 独立 argmax
**替代**：展开为 180 维联合 action → 单一 Q 网络
**理由**：
- 联合空间 180 维中大量无效组合（如 OrderType=market + LimitLevel=improve_1tick）
- 独立 Q 大幅降低样本复杂度
- 与 M4 的 factored model 结构天然对齐
- IQL 的 advantage estimation 在每个 head 独立进行

## 10. 验证计划

### 10.1 奖励函数理智检查（实施后首先验证）

| 检查项 | 预期 | 异常信号 |
|--------|------|----------|
| Hold-only 策略的 episode 总 reward | 显著为负（idle penalty 累积） | ≈ 0 → idle penalty 未生效 |
| Random 策略的 episode 平均 reward | < 0（fee + α_loss 被动亏损 + idle） | ≈ 0 或 > 0 → 惩罚项未生效 |
| 结算 tick 的 reward 方差 | 远大于非结算 tick | 方差相近 → 结算 PnL 未正确包含 |
| 止损 tick vs 扛着 tick 的负 reward | 止损 tick 不放大，扛着 tick 放大 | 止损 tick 更负 → 主动/被动区分有误 |
| 有持仓时 idle penalty = 0 | 持仓 tick 不收 idle | 持仓时也收 → 条件判断错误 |
| 冷启动 tick idle penalty = 0 | 冷启动不收 idle | 冷启动也收 → 冷启动标记未传入 |
| Drawdown penalty 在 NAV 上升时为零 | NAV 创新高 → λ_dd 项 = 0 | 上升时非零 → 增量计算有误 |

### 10.2 超参数敏感性分析（M5 训练前）

在 1 天数据上回放，扫描参数组合，观察：
- 每 market 平均交易次数（应 > 5，否则 idle penalty 不够或 turnover penalty 过重）

- 空仓比例（应 < 50%，否则 idle penalty 不够）

## 11. 伪代码

```python
class RewardCalculator:
    def __init__(self,
                 alpha_loss=1.5,
                 lambda_turn=0.0005,
                 lambda_dd=0.5,
                 lambda_idle=0.0001):
        self.alpha_loss = alpha_loss
        self.lambda_turn = lambda_turn
        self.lambda_dd = lambda_dd
        self.lambda_idle = lambda_idle
        self.prev_nav = None
        self.peak_nav = None
        self.prev_drawdown = 0.0

    def reset(self, initial_nav: float):
        """Call at session start."""
        self.prev_nav = initial_nav
        self.peak_nav = initial_nav
        self.prev_drawdown = 0.0

    def step(self, nav: float, turnover_notional: float,
             has_trade: bool, up_shares: float, down_shares: float,
             is_cold_start: bool) -> float:
        """Call at each decision tick. Returns scalar reward."""
        # 1. Asymmetric ΔNAV (distinguish active vs passive loss)
        delta_nav = nav - self.prev_nav
        if delta_nav >= 0:
            reward_nav = delta_nav
        elif has_trade:
            reward_nav = delta_nav                        # active correction: no amplification
        else:
            reward_nav = self.alpha_loss * delta_nav      # passive holding: amplify loss

        # 2. Turnover penalty
        turn_penalty = self.lambda_turn * turnover_notional

        # 3. Drawdown penalty (incremental only)
        if nav > self.peak_nav:
            self.peak_nav = nav
        current_dd = max(0.0, (self.peak_nav - nav) / self.peak_nav)
        incremental_dd = max(0.0, current_dd - self.prev_drawdown)
        dd_penalty = self.lambda_dd * incremental_dd
        self.prev_drawdown = current_dd

        # 4. Idle penalty (no position + not cold start)
        is_idle = (up_shares == 0 and down_shares == 0 and not is_cold_start)
        idle_penalty = self.lambda_idle if is_idle else 0.0

        # 5. Combine
        reward = reward_nav - turn_penalty - dd_penalty - idle_penalty

        self.prev_nav = nav
        return reward
```

## 12. 开放问题（M5 实施时决定）

1. **Reward normalization**：是否在 IQL 训练中做 reward z-score 归一化？初始 NAV=$100 USDC 时 reward 量级约 ±$0.01~$30（结算 tick 被动亏损放大后更极端）。建议先不归一化，观察训练稳定性后决定。
2. **RiskHead 在 RL 中的角色**：M4 中 RiskHead 作为 soft clip 使用。M5 RL 中是否继续保留 soft clip、还是让 RL 自由学习 RiskHead 的输出？建议保留 soft clip（保持与硬风控的分层结构），但 RL 训练 RiskHead 参数。
3. **多行为策略混合比例**：若采用 random + heuristic 混合数据集，两者比例需实验确定。建议起始 80% random + 20% heuristic。
4. **StateBranch 骨干重训 vs 冻结**：加入 11 个新列后（6 agent state + 5 长期信号），骨干的 InputNormalizer 和 branch 权重需要更新。建议：冻结 TCN/Transformer 骨干，只训练 StateBranch + 5 个 action heads。
