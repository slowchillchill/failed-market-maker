## 2. 当前状态（关键事实）

- `paper-runtime` 6 个子命令通过 smoke；`PaperRuntimeConfig` 18 字段，缺 `strategy / agent_config_path / fixed_size / limit_order_ttl_ms`
- `PaperOrderAdapter` 只 submit/cancel 记录；无 fill / TTL / partial 模拟
- `PaperDecisionRow`（`paper-runtime/src/log_writer.rs:15-40`）实测共 22 字段：13 个非 nullable 状态/数值字段（`signal_*` / `policy_action` / `size_level` / `order_type` / `limit_level` / `risk_score` / `nav` / `cash` / `up_shares` / `down_shares` / `has_gap` / `is_cold_start` 等）+ `order_id / order_event` 已是 `Option<String>` 且 schema nullable=true。§2.3 nullable 改造**只针对 8 个新增 nullable 字段**（signal/size/order/limit/risk_score 中的一部分），不动 `order_id / order_event` 现有 Option 形态

- 离线 polymarket 事件顺序（`replay.rs:401-409`）：先 `maybe_schedule_limit_order_fills`，再 `apply_polymarket_event`；其他 source 只 apply
- 离线主循环顺序（`replay.rs:430-470`）：source/scheduled events → `expire_resting_limit_order` → `on_step` → `on_decision_tick`
- 离线 settlement 路径（`replay.rs:533-558`）：market end 时调 `account.settle_market(&market_state, market.label_up, market.resolution_price)`，再调 `strategy.on_settlement(&settlement)`。`AgentStrategy::on_settlement`（`strategy.rs:433-441`）更新 `settled_pnl_history`，影响 76 维特征 `settled_pnl_last_1/3/6`（`strategy.rs:265-267`）
- 离线 ScheduledEvent 处理（`replay.rs:870-1010`）：`ExchangeArrival` 触发时**同步**调撮合（`execute_*_buy/sell`）已经修改 orderbook 与 cash，并 push `LocalAck` 到 scheduled；`LocalAck` 触发时调 `account.apply_buy_fill / apply_sell_fill` 真正写账户。两阶段中 ExchangeArrival 已经"提交"，paper 的 cancel **不能**抹掉对应 LocalAck，否则丢失成交

- `AgentStrategy::reset_episode(initial_nav)`（`strategy.rs:137-142`）会清 `feature_buffer / settled_pnl_history`，并设 `episode_initial_nav = initial_nav`，导致 `session_return = (cur - initial_nav) / initial_nav`（`strategy.rs:268-272`）

p2b 设定后落 `health.jsonl` 一条 `{"event":"market_p2b_set","value":<…>,"source":"gamma|chainlink"}`。

### 3.7 AgentStrategy 重置语义（**严禁误用**，mirror agent evaluate）

| 触发场景 | 调用 | 副作用 |
|---------|------|-------|
| runtime 启动一次 | `inner.reset_for_reused_window()` | 清 `feature_buffer / settled_pnl_history / risk_state / esm`；`episode_initial_nav = 0.0` → `session_return = 0.0`（else 分支） |
| 每个 5min market 边界 | `inner.before_market(market)` | 重置 `binance_p2b / prev_chainlink_value / step_index / esm / risk_state / baseline_config.reset_market`；**不清 feature_buffer**（跨 market 回看） |
| 模型冷切换 | 重启 runtime | 等价于走第一行；`starting_cash` 仍取 `paper_runtime.json` 的配置值（默认 100），**切换前**必须先 cancel_all_resting + flush trades_writer + 等待 pending_settlements 全部 settle 或写 `unsettled_at_shutdown`；切换后从 100 USDC 重新累计 PnL，与切换前 PnL 在不同 run_manifest 下分别归档 |

**绝不调用** `inner.reset_episode(starting_cash)`。该函数会让 `episode_initial_nav = 100`，导致 `session_return = (cur - 100) / 100`，与 K2-C 离线 evaluate（initial_nav=0、session_return=0）特征不一致，破坏 §6.2.2 parity gate。

  6. 新增公共类型与 facade：
     ```rust
     #[derive(Debug, Clone, Serialize)]
     pub enum PaperFillEventKind {
         Submitted, Cancelled, ExchangeArrival, FilledFull, FilledPartial,
         TtlExpired, LocalAck, RestingPlaced,
         /// cancel 请求到达时订单已无 future ExchangeArrival 也不 resting，
         /// 仅剩 pending LocalAck（撮合已发生，等 ack 写账户）。
         /// 此时 cancel 不能抹掉 LocalAck，订单保持 active 直到 ack 完成。
         CancelRejectedPendingAck,
     }
     
     #[derive(Debug, Clone, Serialize)]
     pub struct PaperFillEvent {
         pub event_ts_ms: i64,
         pub kind: PaperFillEventKind,
         pub order_id: String,
         pub market_id: String,
         pub side: Option<String>,                 // "buy"|"sell"
         pub outcome: Option<String>,              // "up"|"down"
         pub filled_shares: Option<f64>,
         pub avg_fill_price_ticks: Option<i64>,
         pub fee_usdc: Option<f64>,                // taker fee；maker fill 为 0
         pub rebate_usdc: Option<f64>,             // maker rebate；taker fill 为 0；
                                                    // **直接取自 replay-engine 的 maker_rebate_usdc 计算**
                                                    // (`replay.rs:2581-2586`)，不要由 fee_usdc 推导
         pub proceeds_usdc: Option<f64>,           // sell-side: filled_shares × avg_fill_price；buy-side None
         pub sold_cost_basis_usdc: Option<f64>,    // sell-side: 卖出股数对应的 cost basis（按当前持仓平均成本）；buy-side None
         pub realized_pnl_usdc: Option<f64>,       // sell-side / settlement only；其他 kind None；公式见 §2.5
         pub fill_status: Option<String>,          // "filled"|"partial_fill"|"no_fill"
     }
     
     pub struct LiveExecutionDriver {
         // 私有类型留在 module 内。scheduled 处理时按 ts_ms 升序，到期就 pop。
         // active_orders 移除时机：LocalAck 完成、TtlExpired、Cancelled、close_market drain。
         scheduled: Vec<ScheduledEvent>,
         active_orders: HashMap<String, OrderIntent>,
         runtime_config: RuntimeConfig,
     }
     
     impl LiveExecutionDriver {
         pub fn new(runtime_config: RuntimeConfig) -> Self;
     
         pub fn submit(
             &mut self,
             intent: OrderIntent,
             market_state: &mut ActiveMarketState,
             account: &mut AccountState,
             now_ms: i64,
         ) -> PaperFillEvent;
     
         /// 取消单笔订单。撮合一旦在 ExchangeArrival 触发后已写入 ActiveMarketState

         /// ExchangeArrival/LocalAck 会推后到 source event 之后，账户与 on_step 漂移。

         /// （§1.3 第 5 步）的"第一轮 scheduled 优先"判定靠这个。

             market_state: &mut ActiveMarketState,

         ///
         /// - `CloseMode::StrictByEnd { end_ts_ms }`（A 路 / run-recorded 用）：
         ///   只 drain `intent.market_id == old_market_id && ts_ms <= end_ts_ms`
         ///   的 scheduled 事件，按 ts_ms 升序立即处理。完成后 leftover

             account: &mut AccountState,
             mode: CloseMode,

         StrictByEnd { end_ts_ms: i64 },
     ```

        2. 用 `std::mem::replace(&mut market_state, ActiveMarketState::new(next_descriptor, next_asset_map)?)` 把旧 state move 出来，新 state 替换进去
        3. `pending_settlements.insert(old_market_id, old_state)`（old_state 含 market.p2b）
        4. 调 `logger.before_market(&market_state.market)`（不清 feature_buffer，跨 market 回看保留）
        5. 重置 `p2b_initialized = false`，p2b 重新初始化（§3.5）
      - 收到 Polymarket `market_resolved` ws 事件后异步处理：
        1. 用 `winning_asset_id` 字段（`polymarket-docs/WebSocket Market Channel.md:188-190` 实测 schema）匹配 paper-runtime 缓存的 market `clobTokenIds[outcomes.indexOf("Up"|"Yes")]`，得出 `label_up: bool`
        2. `winning_outcome` 字符串作为 sanity check（BTC UP/DOWN 用 "Up"/"Down"，其他二元 market 用 "Yes"/"No"，不直接依赖）
        3. 从 `pending_settlements.remove(market_id)` 拿出 `old_state`
        4. 调 `let settlement = account.settle_market(&old_state, label_up, resolution_price);`（直接 mutate 全局 account：`replay.rs:1292-1314` 实测 `&mut self`，按 market_id 移除 inventory/cost_basis 并 cash += payout）
        5. `logger.on_settlement(&settlement)`（forward 到 `inner.on_settlement` 更新 `settled_pnl_history`；该更新对当前 market 的特征生效，与离线"market end 立即 settle"略有延迟差异，B 路 tolerance 容忍）
        6. `health.jsonl` 写 `{"event":"market_resolved","market_id":..,"label_up":..,"resolution_price":..,"realized_pnl_usdc":..,"settle_lag_ms":<now - end_ts_s*1000>}`
        7. `trades_writer.write_settlement(market_id, label_up, resolution_price, p2b=old_state.market.p2b, realized_pnl_usdc, settle_lag_ms, ts_ms)`
      - shutdown 时 pending_settlements 中所有未结算 market：写 `health.jsonl` 一条 `{"event":"unsettled_at_shutdown","market_id":..,"end_ts_s":..}`，不强制 settle
  8. gap 处理：`gap_state()` 中任一 source `> 15_000` → `live_driver.cancel_all_resting(&mut market_state, now_ms)` → 全部取消，每条 fill 同样写 trades/health → `health.jsonl` 写 `gap`；标记 `shadow_invalid`，本 market 内不再决策
  9. shutdown 顺序（SIGTERM / Ctrl-C / `--until-iso` 到期）：
     1. 停接 source（关 mpsc receiver）
     2. `live_driver.cancel_all_resting(&mut market_state, now_ms)` → 写 trades / health
     3. 主循环 drain 所有 pending PaperFillEvent（避免漏写）
     4. `pending_settlements` 中所有未结算 market 写 `health.jsonl` `unsettled_at_shutdown`
     5. `trades_writer.flush()?` + `parquet_writer.finish()?` + `health_writer.flush()?`
     6. 写 `run_manifest.json` 末状态（`end_ts_ms / unsettled_count / total_decisions`）
     7. exit
  10. `--record-raw-events` 时，把 visibility gate admitted 后的 **normalized event** tee 到 `<output_dir>/raw/{market,live,relay}.ndjson`，每行 schema：
      ```json
      {"source":"polymarket"|"orderbook"|"aggtrade"|"chainlink",
       "source_rank":0|1|2|3,
       "source_seq":<u64,该 source 内单调递增>,
       "payload_ts_ms":..,"rx_ts_ms":..,"visible_ts_ms":..,
       "raw_payload":{...原始 ws 消息内容...}}
      ```
      固定 source_rank：polymarket=0、orderbook=1、aggtrade=2、chainlink=3（与离线 `replay.rs:400-422` 同 timestamp 优先级一致）。**run-recorded 直接消费 visible_ts_ms，不重跑 visibility gate**；同 visible_ts_ms 按 (source_rank, source_seq) 升序，保证与 dump_window_as_recording 的离线 dump 字节级一致

- `replay-shadow`：用 `DecisionLoggingStrategy::new(AgentStrategy::new(...)?, writer, ...)?` 调 `ReplayEngine::run_with_strategy(ReplayConfig{dataset_version, window_id, ...}, &mut wrapper)`。ReplayEngine 自身已经按 source-events → on_step → on_decision_tick → settle_market → on_settlement 顺序驱动，wrapper 不需要重排
- `run-recorded`：**deterministic virtual clock**（mirror `replay.rs:569-583` 的 next_market_timestamp 语义）——
  - 时钟从 recording 第一条 `visible_ts_ms` 开始
  - 每个 step 的 next clock 严格 = `min(next_recording_event.visible_ts_ms, live_driver.next_scheduled_ts(), wrapper.schedule_next_tick(), market_end_ms)`，与离线 `next_market_timestamp` 完全同序
  - 任何 source event 处理前，必须先 drain 所有 `scheduled.ts_ms <= event.visible_ts_ms` 的事件（保持 ExchangeArrival/LocalAck 在正确时点 ack 账户，否则 on_step 看到的 cash/positions 会落后）
  - 不使用 tokio interval、不使用 wall clock
  - **A 路 market boundary hook 顺序**（必须严格按此序，否则 obs/model/nav ≤ 1e-6 失败；变量命名约定：`market_state` 始终指向"当前活跃 market"，`old_state` 是被 replace 出来的"已结束 market"）：
    1. 处理所有 `ts <= end_ts_ms` 的 source / scheduled / decision tick 事件（用当前 `market_state`，它就是即将结束的 old market）
    2. 从 boundary_events 内存索引查 old market 的 boundary 数据（label_up / resolution_price / p2b / winning_asset_id / winning_outcome）
    3. 用 recording_manifest 的下一个 market 数据构造 `next_state = ActiveMarketState::new(next_descriptor, next_asset_map)?`
    4. `let mut old_state = std::mem::replace(&mut market_state, next_state);`（此后 market_state 指向 new，old_state 持有 old）
    5. `live_driver.close_market(old_market_id, &mut old_state, &mut account, CloseMode::StrictByEnd { end_ts_ms })?` 只 drain `ts_ms <= end_ts_ms` 的旧 market scheduled（mirror `replay.rs:580` 的 `next_scheduled.filter(|ts| *ts <= market_end_ms)` 同口径）；leftover `ts_ms > end_ts_ms` → Err → A path bug，立即停下定位，不进入下个 market；drain 出的 fill events 全部 `note_order_event` + `trades_writer.write` + `health.jsonl`
    6. `let settlement = account.settle_market(&old_state, boundary.label_up, boundary.resolution_price);`（直接同步 settle，不走异步 pending_settlements 路径）
    7. `logger.on_settlement(&settlement)` 立即更新 `settled_pnl_history`；写 `health.jsonl` + `trades_writer.write_settlement(...)`（含 `p2b = old_state.market.p2b`）
    8. `logger.before_market(&market_state.market)`（new market）
    9. `market_state.set_p2b(boundary_for_new_market.p2b)`（来自 recording_manifest 的下一个 market boundary 数据，source = `recording_manifest`），`p2b_initialized = true`
    10. 进入新 market 的事件循环
  - **B 路（真实 live recording）**：`market_resolved` 没有 `synthetic` 标志位，走 §1.3 第 7 步异步 pending_settlements 路径，`settle_lag_ms > 0`，由 B 路 tolerance 容忍

  ```json
  // Settlement 行（kind = "settlement"，含 p2b 供 B 路 converter 读）
  {"ts_ms":..,"kind":"settlement","market_id":..,"label_up":..,
   "resolution_price":..,"p2b":..,"realized_pnl_usdc":..,"settle_lag_ms":..}
  ```
- **`realized_pnl_usdc` 公式（写死）**：
  - **Settlement 行**：`payout_usdc - cost_basis_up - cost_basis_down`（来自 SettlementLog 字段，`replay.rs:213-224`）
  - **Sell fill 行**（`side == "sell"`）：`proceeds_usdc - fee_usdc + rebate_usdc - sold_cost_basis_usdc`
    - `proceeds_usdc` 直接取 PaperFillEvent.proceeds_usdc 字段
    - `fee_usdc` 直接取 PaperFillEvent.fee_usdc（taker fill 为正、maker fill 为 0）
    - `rebate_usdc` **直接取 PaperFillEvent.rebate_usdc 字段**（来源 `replay.rs:2581-2586` 的 `maker_rebate_usdc(fill_shares, price, taker_fee_rate, maker_rebate_rate)`，是 hypothetical taker fee × maker rebate rate；taker fill 为 0；**不要**由 fee_usdc × 0.2 推导，maker fill 的 fee_usdc 本身是 0）
    - `sold_cost_basis_usdc` 直接取 PaperFillEvent.sold_cost_basis_usdc（卖出股数 × 当前持仓平均成本）
  - **Buy fill 行**（`side == "buy"`）：`realized_pnl_usdc = null`（买入无已实现 PnL）
  - **其他 kind**（Submitted / Cancelled / RestingPlaced / TtlExpired / CancelRejectedPendingAck）：`realized_pnl_usdc = null`
- §1.3 主循环每条 PaperFillEvent + market_resolved 都 `trades_writer.write*`
- 测试：mock 5 类 fill event + 1 个 settlement → trades.jsonl 每行 valid JSON 且字段完整
- Commit：`feat(paper-runtime): trades.jsonl writer for per-fill events`

### 3.1 A 路 — 离线 deterministic parity

#### 3.1.1 离线 window → record 兼容 ndjson 转换器

- 新建 `scripts/dump_window_as_recording.py`：
  - 输入：`--dataset-version data-v1 --window-id <…> --output-dir <…>`


  - 同 visible_ts_ms 排序键固定为 `(visible_ts_ms, source_rank, source_seq)`，对齐 `replay.rs:400-422` 的 polymarket → orderbook → aggtrade → chainlink 优先级
  - **关键 1（market start p2b）**：`recording_manifest.json` 必须包含每个 market 的完整 boundary 数据：
    ```json
    {"markets":[
      {"market_id":..,"start_ts_s":..,"end_ts_s":..,"asset_map":{"up":..,"down":..},
    ```


    run-recorded reader 启动时把 boundary_events 全部加载到内存（per-market 索引），主循环在 §1.3 `run-recorded` 子节 A 路 boundary hook 触发时直接查表，普通 source loop 永远不会处理它

    - `final_unrealized_pnl`：聚合器按 market 分组取 decisions.parquet 末行，但**必须区分 settled vs pending**：
      - **判定规则**：扫 trades.jsonl 收集所有 `kind == "settlement"` 行的 `market_id` → settled_markets set；decisions.parquet 中 market_id ∉ settled_markets 的视为 pending
      - **已结算 market 跳过**：settle_market 调用后 `account.inventory[market_id]` 与 `account.cost_basis[(market_id, Up/Down)]` 都已 remove（`replay.rs:1299-1307`），decisions.parquet 末行的 cost_basis_up/down 与 up/down_shares 应已为 0；如发现非零，记 `pnl_reconcile_diff` 警告但不计入
      - **pending market 计算**：`Σ_pending_market (up_liquidation_value + down_liquidation_value - cost_basis_up - cost_basis_down)`，公式取 decisions.parquet 末行字段
      - **必须用 liquidation_value 而非 mid**——与项目 NAV 口径一致（`replay.rs:1259-1290` nav 内部用 liquidation_value，CLAUDE.md "NAV 按当前可见 Polymarket 盘口的保守立即平仓价值估值，不用 mid price"）
    - **sanity check（严格口径）**：`realized_pnl + final_unrealized_pnl ≈ nav_end - starting_cash`，差超过 0.01 USDC 写 `paper_aggregate.json` 的 `pnl_reconcile_diff` 字段并 stderr WARN（账户口径 bug，但不阻塞聚合）
    - **sanity check（宽松口径）**：当周内所有 market 都 flat 且 settled（即无 pending inventory）时，`realized_pnl ≈ nav_end - starting_cash`（差 < 0.01 USDC）；否则跳过此 check
    - `mean_max_drawdown_pct`：decisions.parquet 按 market 分组取 nav 序列算 max_drawdown，再均值
    - `mean_trades_per_market`：trades.jsonl 中 `kind in {FilledFull, FilledPartial}` 行数 / market 数
    - `mean_flat_ratio`：decisions.parquet 中 `up_shares==0 && down_shares==0` 的 ready 行占比
    - `winning_windows / losing_windows`：按 market 末次 settlement realized_pnl 正负计数（无 settlement 的 pending market 跳过）
    - `churn_ratio`：trades 中 fill 总 notional / starting_cash / market 数
    - `hit_ratio`：trades 中 sell 类 realized_pnl > 0 的占比
