# M3 第三轮超参数搜索方案

基于两轮 20 组实验结果，设计第三轮搜索。本轮重点：**验证 seq=100 的可复现性 + 训练技术改进 + 轻度正则探索**。

## 一、前两轮核心发现

### 1.1 总冠军 R04 (seq=100) 的特征

| 指标 | R04 | E05 (旧冠军) |
|------|-----|-------------|
| top_decile_mean_ev_up | **+0.5471** | +0.4589 |
| ev_up_sign_acc | **0.6522** | 0.6063 |
| AUC | 0.7303 | 0.7190 |
| ECE | 0.2485 | 0.3057 |
| ev_rank_corr | 0.0581 | 0.0251 |
| best_epoch | 5 | 7 |
| 有效训练窗口 | ~5 epochs | ~7 epochs |

### 1.2 关键规律

1. **seq_len 响应曲线非单调且有尖锐峰值**：seq=100(+0.547) >> seq=120(+0.459) > seq=60(+0.414) >> seq=90(+0.237)。seq=90 的异常低值令人困惑。
2. **短序列是最有效的正则化**：在 seq=120 上叠加 dropout/wd 的 B 组实验全部不如纯 E05。
3. **过拟合仍然严重**：R04 在 ep5 达到 val peak（+0.389），ep6-10 快速衰减。train_loss 从 2.22 降至 0.60，降幅 73%。
4. **CosineAnnealingLR 在早停场景下几乎无效**：T_max=30 时 ep5 的 LR 仅衰减 ~13%，模型实质上在用近乎恒定的学习率训练。
5. **校准与盈利能力 tradeoff**：R05（强正则）ECE=0.0998 最佳，但 top10_ev 仅 +0.19。

## 二、第三轮设计策略

### 2.1 三个核心问题

1. **seq=100 的优势是否可复现？** seq_len 响应曲线的尖锐峰值可能是随机噪声。需要重跑验证，并测试 95~110 邻域。
2. **训练技术能否延长有效学习窗口？** 当前 5 个 epoch 的窗口太短，通过 label smoothing、warmup、Huber loss 等手段可能改善。
3. **轻度正则在 seq=100 上效果如何？** Round 2 仅测试了 seq=120 + 强正则（失败），但从未在 seq=100 上测试过轻度正则。

### 2.2 需要的代码修改

需要 4 项小改动（均为新增 CLI 参数 + 少量代码）：

| 改动 | 文件 | 改动量 | 说明 |
|------|------|--------|------|
| `--label-smoothing` | loss.py + train.py | ~3 行 | `cross_entropy(label_smoothing=X)` |
| `--warmup-epochs` | train.py | ~8 行 | LinearLR + CosineAnnealingLR 组合 |
| `--ev-loss-fn` | loss.py + train.py | ~5 行 | 支持 `mse` / `huber` 切换 |
| `--nhead` | train.py | ~2 行 | 传递到 TinyCausalTransformer |

### 设计逻辑

**A 组：seq_len 精确定位 + 复现验证（T01-T04）**

- **T01 (seq=95)**：100 的左邻域。如果 95 也好，说明最优区间是 95-100 而非刚好 100。
- **T02 (seq=105)**：100 的右邻域。测试 100→120 之间的下降梯度。
- **T03 (seq=110)**：100→120 的中点。如果 110 ≈ 120，说明 100 是孤立峰。
- **T04 (复现)**：完全相同参数重跑 R04，验证 +0.5471 是否可复现。如果复现值显著偏离（如 ±0.10），说明 seq=100 的优势包含较大随机成分。

目标：确认最优 seq_len 区间，评估结果方差。

**B 组：训练技术改进 at seq=100（T05-T08）**

- **T05 (Label Smoothing 0.1)**：CrossEntropyLoss 的 label_smoothing=0.1 将硬标签 [0,1] 变为 [0.05, 0.95]，直接降低模型过度自信，预期改善 ECE。对 top10_ev 的影响待验证——可能通过减少过拟合间接提升。
- **T06 (Warmup + 长训练)**：前 3 个 epoch 从 0 线性升到 lr=4e-4，之后 CosineAnnealing。稳定早期训练（R04 的 ep1-2 可能存在 LR 过大的问题）。配合 epochs=50 + patience=10 延长搜索。
- **T07 (Huber EV Loss)**：将 EV 回归的 MSELoss 替换为 SmoothL1Loss（Huber），对 EV 异常值更鲁棒。当 |error| > 1 时梯度恒定为 1（不爆炸），可能改善 sign_acc 和 rank_corr。
- **T08 (综合)**：Label Smoothing 0.05（较温和） + Warmup 2ep + Huber。如果 T05-T07 分别有效，组合可能叠加收益。

**C 组：新维度 at seq=100（T09-T10）**

- **T09 (8 头注意力)**：当前 nhead=4，d_model=128 → 每头 32 维。增加到 nhead=8（每头 16 维）让注意力可以学习更多种类的时间依赖模式，参数量不增加（是 multi-head 内部分割）。
- **T10 (轻度正则)**：dropout 0.1→0.15、wd 1e-4→2e-4，仅轻微增加。Round 2 证明重度正则有害，但从未在 seq=100 上测试过轻度正则。配合 patience=8 给模型更多探索时间。

## 四、代码修改详情

### 4.1 loss.py — 新增 label_smoothing 和 ev_loss_fn 支持

```python
# signal_loss 函数签名变更:
def signal_loss(
    logits, ev_pred, y_cls, y_ev_up, y_ev_down, y_ev_mask,
    lambda_cls=1.0, lambda_ev=0.5,
    label_smoothing=0.0,        # 新增
    ev_loss_fn="mse",           # 新增: "mse" | "huber"
):
    # 分类损失：加入 label_smoothing
    cls_loss = nn.functional.cross_entropy(logits, y_cls.long(), label_smoothing=label_smoothing)

    # EV 回归损失：支持 mse / huber
    if y_ev_mask.any():
        ev_pred_valid = ev_pred[y_ev_mask].float()
        ev_tgt_valid = ev_target[y_ev_mask]
        if ev_loss_fn == "huber":
            ev_loss = nn.functional.smooth_l1_loss(ev_pred_valid, ev_tgt_valid)
        else:
            ev_loss = nn.functional.mse_loss(ev_pred_valid, ev_tgt_valid)
    ...
```

### 4.2 train.py — 新增 CLI 参数

```python
# parse_args() 中新增：
p.add_argument("--label-smoothing", type=float, default=0.0,
               help="Label smoothing for CrossEntropyLoss (0.0-0.2). Default: 0.0")
p.add_argument("--warmup-epochs", type=int, default=0,
               help="Linear LR warmup epochs before cosine decay. Default: 0")
p.add_argument("--ev-loss-fn", choices=["mse", "huber"], default="mse",
               help="EV regression loss function. Default: mse")
p.add_argument("--nhead", type=int, default=4,
               help="Number of attention heads in TinyCausalTransformer. Default: 4")
```

### 4.3 train.py — Scheduler 修改

```python
# 替换原有的 scheduler 创建逻辑：
if args.warmup_epochs > 0:
    warmup_scheduler = torch.optim.lr_scheduler.LinearLR(
        optimizer, start_factor=1e-3, end_factor=1.0, total_iters=args.warmup_epochs
    )
    cosine_scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(
        optimizer, T_max=args.epochs - args.warmup_epochs
    )
    scheduler = torch.optim.lr_scheduler.SequentialLR(
        optimizer, schedulers=[warmup_scheduler, cosine_scheduler],
        milestones=[args.warmup_epochs]
    )
else:
    scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=args.epochs)
```

### 4.4 train.py — nhead 传递

```python
# model 创建时传递 nhead：
model = PolyArbSignalModel(
    seq_len=args.seq_len,
    d_model=args.d_model,
    n_transformer_layers=args.n_transformer_layers,
    nhead=args.nhead,        # 新增
    dropout=args.dropout,
).to(device)
```

### 4.5 train.py — loss 调用修改

```python
# train_epoch 和 eval_epoch 中的 signal_loss 调用：
loss, cls_l, ev_l = signal_loss(
    logits, ev_pred, y_cls, y_ev_up, y_ev_down, y_ev_mask,
    lambda_cls=lambda_cls, lambda_ev=lambda_ev,
    label_smoothing=label_smoothing,   # 新增
    ev_loss_fn=ev_loss_fn,             # 新增
)
```

## 八、第三轮结果分析

### 8.1 核心发现：R04 的 +0.5471 包含显著随机成分

**复现验证失败**：T04（完全相同参数）仅达到 +0.3797，与 R04 相差 **-0.167**。这远超 0.05 的稳定性阈值，说明 R04 的 +0.5471 中约 0.17 来自随机种子/训练噪声。

seq=100 的"真实"期望性能约为 **+0.38~+0.40**，而非 +0.55。

### 8.2 seq_len 响应曲线修正

考虑 T04 复现数据后，seq_len 响应曲线不再有尖锐峰值：

```
seq:     60    90    95   100  100*  105   110   120   150   180   240   480
top10:  0.41  0.24  0.29  0.55  0.38  0.40  0.10  0.46  0.27  0.44  0.25  0.19
                          ↑luck ↑real
```

修正后的规律：
- **seq=100~120 是宽泛的最优区间**（期望 +0.38~+0.46），不存在 100 的孤立峰
- seq=90 和 seq=110 是两个异常低谷，可能与 dataloader 的跨 market 拼接边界有关
- 短序列（60~120）整体优于长序列（150~480）的结论依然成立

### 8.3 训练技术效果评估

- **T08 综合组合** 达到 +0.4834 和 best_ep=8，但考虑到 R04 的随机性教训，这个高值也可能包含运气成分

### 8.7 综合结论与建议

1. **top10_ev 指标的方差很大**（~0.17 的随机噪声），单次实验结果不可作为可靠排名依据
2. **seq=100~120 是稳健的最优区间**，在这个范围内多次实验的均值约 +0.38~+0.46
3. **Huber Loss 是确认有效的改进**：不损失 top10_ev，轻微改善 ECE 和 sign_acc
4. **Label Smoothing 适合需要校准的场景**，但会牺牲 top10_ev
5. **正则化（包括轻度）在短序列上一致有害**
6. **建议 M4/M5 使用 T08 配置**（seq=100 + label_smoothing=0.05 + warmup=2 + Huber），或 R04 配置（如果只看最高单次成绩）
