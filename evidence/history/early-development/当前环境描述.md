## 当前数据口径

- 新数据集版本必须使用 `model/data-v*/<window_id>/...` 目录结构。
- 当前代码不会把 `model/data-v*/<date>/<window_id>/...` 识别为正式窗口目录；旧文档里的这类示例已过时。
- `M0` 正式索引层产物是：
  `manifest.parquet + labels.parquet + validation.parquet + tables/*.parquet`
- `manifest.parquet` 不直接包含 `p2b / resolution_price`；这两项在 `labels.parquet`。
- 下游回放、特征、训练不能只读 `manifest.parquet`，必须联合消费 `manifest + labels`。
- `feature-engine` 当前正式输出口径为 `86` 列；其中 `M2` 历史初版是 `79` 列，`M5 S1` 扩展后新增 `agent_cash / agent_nav` 与 `5` 列长期信号，形成当前 canonical schema。
- `M3 Phase 1` 实际监督输入是 `FEATURE_COLS = 65`；`M5/M6` 的 observation 输入是 `76` 维。
- `feature_stats.npz` / `feature_stats_76.npz` 是训练-导出-追溯链路上的契约工件；当前 Rust ONNX runtime 不直接读取它们，因为 normalizer 已烘入 ONNX 图，但模型与对应 stats 仍必须成套保存。
- 若联合多个数据集训练，必须先全局合并 parquet，再统一做严格时间前推切分；不能“各文件各自切分后再拼接”。

## DATA-V4 相关提醒

- `data-pipeline` 已支持自动发现 `data-v*`，因此 `validate/export` 可直接用于 `data-v4`。
- `backfill_binance_btcusdt_aggtrades_ms.py` 可直接用 `--dataset-version data-v4`。
- `sync_polymarket_asset_map_overrides.py` 的默认扫描列表仍是 `data-v1 data-v2 data-v3`；处理 `data-v4` 时必须显式传 `--datasets data-v4`。
- 若未来为 `data-v4` 生成 `tick_stream`，默认应使用 `reward_minimal` 口径，或在采集时显式关闭 `reward_clip`；旧的 clipped reward 只保留为历史对照。
