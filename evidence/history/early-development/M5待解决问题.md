## 1. 背景：M5 想解决的问题

M5 阶段目标是用**离线 RL (IQL)** 把 M3 预训练的 signal backbone 升级成一个**完整决策 agent**：
方向 + 仓位 + 下单方式 + 限价 + 持有/减仓/平仓/反手。

训练范式：
1. 用 M3 backbone + softmax 探索策略，在回放引擎上跑出 transition 数据（`tick_stream/*.parquet`）
2. 对 transitions 做 offline IQL 训练（FactoredQNetwork + ValueNetwork + AWR 提取 policy）
3. 在 held-out windows 上评估 agent 的 Sharpe / 净 PnL / 交易行为

预期结果：agent 在测试 split 上 Sharpe>0，交易 ≥5 次/market，不退化成全空仓。

## 2. 真正的问题：Policy 塌缩到 100% Hold

从 m5_run2 → m5_run3 → m5_run4 → m5_run4b → m5_run5，所有实验训练出的 policy 都呈现同一症状：

- **Policy argmax 几乎总是 Hold**（100% flat on test split）
- **Policy loss 早期小幅下降后 plateau**（例：m5_run4b 完全 frozen 在 4.69，m5_run5 从 5.25 → 4.62 后 plateau）
- **Q/V loss 仍在下降**，说明 Q 函数在学，但 policy head 没跟上
- **Signal head 仍有方向性**（55% down / 45% up），说明 M3 backbone 的预测能力还在，只是 **policy head 没有利用它**

Phase 11.7 ～ 11.8-F 已经排除的假设（早期排障细节见 `M5故障文档.md`，该文档现为历史归档）：

- ❌ `size_mapping` 语义 bug（11.1 已修）

## 3. Phase 11.8-H 三大诊断结论（关键事实）

为了跳出"调超参 → 再训 → 失败"的循环，我们跑了三个**不依赖采集策略 PnL** 的诊断：

### 3.1 Oracle 理论上限 = **+94%** 每笔

- 假设 t=0 就知道 `label_up`，全仓买正确方向持有到结算
- 平均 return：**+94.0%**
- 100% episodes 正收益
- 两种 label 对称（+93% vs +95%）
- BTC 窗口内变动：mean +0.0002%, std 0.15%

**结论**：**数据里有巨大的套利空间**。二元期权的 ask price 没有完美反映最终方向，只要猜对方向就能赚。

### 3.2 M3 signal head 方向准确率 = **54.1%**（基准 48.9%）

（用 `action_policy` 做 proxy，因为 tick_stream 没存 signal_logits）
- OpenUp 正确率：52.9%
- OpenDown 正确率：55.5%
- **M3 边际 alpha ≈ +5.2 pct**

简单 EV 计算：`0.541 × 0.94 + 0.459 × (-1.0) = +4.95%` 每笔。**存在可利用的正期望**。

### 3.3 条件期望 — 揭示真正的 bug

在**旧 reward（reward_clip=1.0）**下：

```
mean reward:                       label_up=False   label_up=True
  Hold                                -0.01040       -0.00504
  OpenUp                              -0.00831       -0.00842     ← 方向对错几乎一样
  OpenDown                            -0.00692       -0.00862
  Close                               +0.00163       +0.00153
  Flip                                +0.00088       +0.00033

E[reward | OpenUp 正确] - E[reward | OpenUp 错误] = -0.00011
```

Per-episode 累计 reward：
- label_up=True:  mean **-5.20**
- label_up=False: mean **-8.72**

即便方向对了，整个 episode 累计下来仍然是**亏**的。

### 3.4 根因：时间尺度失配 + reward_clip 斩断信号

- Reward 是**每 tick 定义**的（`nav_delta - idle − turnover − dd`）
- **信号是 episode-level 的**（结算时才知道 label）
- 开仓那 tick 只有 `spread + fee` 的固定负值，alpha 在未来通过 γ 传播
- **`reward_clip = Some(1.0)`** 把结算时的 ±20 跳变 clip 成 ±1，**信号直接被斩断**
- `idle_penalty` + `dd_penalty` + `alpha_loss=1.5` 再额外每 tick 累积噪声
- IQL 正确学到了"所有单步 action 期望负向"，AWR 正确提取了"Hold 最安全"

## 5. 根因分析（更新版）

### 5.1 IQL/AWR 在当前数据结构下的结构性困难

观察到的事实：
- Q loss 一直在下降，Q 函数在学
- 但 Q 值范围很窄（V̄ ≈ -0.30，q_loss ≈ 0.04 → Q 差异 ≈ 0.2）
- AWR 权重 = `exp((Q-V)/β)`，β=3.0 时 weight ratio ≈ exp(0.2/3) ≈ 1.07 → **几乎 uniform**
- Policy 梯度近乎 0，无法 escape 初始 Hold-dominant 分布

**为什么 Q 值范围这么窄？** —— γ 传播衰减：
- 单 episode 约 1200 ticks
- γ=0.9995 → `0.9995^1200 ≈ 0.549`，结算 reward +10 传播到开仓点只剩 ~5.5
- 中间 1199 个 tick 的 nav noise（std ~0.1）在累积 return 上贡献 ~√1199 × 0.1 ≈ 3.5 的噪声
- **Signal-to-noise ratio ≈ 5.5 / 3.5 ≈ 1.6**，太低
- Q 函数在噪声里学不稳，最终学到的是"所有 action 的 Q 差异都很小"

### 5.2 为什么 Q 对 Hold 依然 bias

- Hold 样本占 58%，Q(s, Hold) 的**统计精度**更高
- 其它 action 样本少，Q 估计方差大
- 加上 expectile τ=0.7 的 pessimistic bias，Q(s, 其它) 被压低
- **结果**：Q(s, Hold) 系统性高于 Q(s, 其它) → AWR 给 Hold 最大权重

### 5.3 结构性结论

**当前数据 + IQL 框架的组合在结构上不适合这个任务**。具体：

| 要素 | 现状 | 影响 |
|---|---|---|
| Reward sparsity | 绝大部分 tick 是 spread noise，信号只在结算 tick | TD 必须跨 1200 tick 传播 |
| γ 衰减 | γ^1200 ≈ 0.55 | 结算 signal 回流时强度减半 |
| Action 分布 | Hold 58% 主导 | Q(Hold) 学得最准 |
| Behavior policy EV | 净负 (-1.35% 平均) | offline RL 天然保守 |

**offline RL 的核心假设是"数据里存在好的 action"**，但本任务里"好的 action"的 reward signal 被噪声 + 衰减淹没了。即便 **数据里有 alpha**（诊断已证明），**IQL 学不出来**。

### 5.4 Phase 11.8-J1 补充线索：run5 初始化更像在伤害“可交易性”而不是“可分类性”

在同一 frozen split、同一 `Oracle-B + freeze_scope=j1` 条件下：

- `J1_B_fromM3`：`val_acc=0.7098`，`test_acc=0.6799`，held-out `agent evaluate mean_return=-81.65%`
- `J1_B_fromRun5`：`val_acc=0.7116`，`test_acc=0.6898`，held-out `agent evaluate mean_return=-89.56%`

这说明：

- run5 初始化**没有**把监督方向学习能力打没，甚至分类指标略高
- 但 run5 初始化对应的表示在真实交易回放里更差，说明问题更可能出在 **fusion/state 路径对“可交易决策”的表征已被 IQL 扭曲**，而不只是 policy head 没学到标签
- 因此 Phase 11.8-K 默认应从 `J1_B_fromM3` warm-start，而不是从 `J1_B_fromRun5` 接着 fine-tune

## 6. 历史建议方案（已执行完毕）

以下内容保留当时的分叉决策记录，用于解释为什么后续会进入 J / K 路径；它们不再表示当前仍待执行的任务。

### 6.1 方案对比表

| 方案 | 核心思路 | 工程量 | 成功概率 | 风险 |
|---|---|---|---|---|
| **A**. 降 β=1.0 / 0.5 重训 | 尖锐化 AWR 权重 | 极小（1 行参数） | **低** | Q 本身 flat, 尖锐化也没用 |
| **B**. 降 γ=0.995 + 降 β | 缩短 TD horizon | 极小 | **低** | 短 γ 让 local reward 主导, local 对开仓全负 |
| **C**. Monte Carlo return reward shaping | 把 episode 总回报分摊给每个 tick | 中（~50 行 Python） | 中 | 增大方差, 需要重训 |
| **D**. Filtered BC（Option Z） | 监督学习：学"赢家 episode 的 action" | 中（~100 行新代码） | **中高** | 是监督不是 RL, 与 M5 原计划偏离 |
| **E**. Oracle-guided BC | 直接用 label_up 做监督：label=True 时学 OpenUp，反之学 OpenDown | 中（~80 行） | **高** | 是**作弊版监督**, 上限 = M3 + label leakage, 不是 RL |
| **F**. Reward shaping with signal head | 在 tick reward 里加 `β × log P(signal = correct direction)` | 中 | 中 | 需要修改 Rust reward 计算, 重采集 |
| **G**. Hybrid：先 BC warm-start, 再 IQL fine-tune | 用 BC 给 policy head 一个非 Hold 的初始化, 再跑 IQL | 大 | **高** | 工程量最大, 但可继承原 M5 目标 |

### 6.2 推荐顺序

**第一步：立即做 E (Oracle-guided BC)** —— **不是最终方案, 是诊断**

- 只有一个目的：**验证 backbone + policy head 能不能学出 directional policy**
- 假设是"policy head 学得动，只是 IQL 的 reward signal 不够"
- 如果 Oracle-guided BC 都学不动 → 说明是 **架构问题**，需要改 model
- 如果 Oracle-guided BC 轻松达到 >90% 方向一致性 → 证明 IQL 的 reward signal 才是瓶颈
- **工程量小（不改 Rust, 只加一个 Python 训练脚本）**
- 0.5-1 小时能出结论

**第二步（根据 E 的结果分叉）**：

- 如果 E 成功：
  - **G (Hybrid BC → IQL)**：用 Oracle-guided BC 得到的 checkpoint 作为 IQL 初始化, 再跑少量 IQL epoch, 让 Q/V 适配 RL objective 同时 policy 不塌缩回 Hold
  - 或者直接接受 **D (Filtered BC)** 作为最终方案, 放弃 RL, 交付一个纯监督的 agent
- 如果 E 失败（policy 连 label 监督都学不动）：
  - 说明 policy head 架构本身有问题（可能是 11.8-E 的"policy 不看 agent state"改动削弱了表达能力）
  - 需要回到架构调查, 做 ablation

**第三步：如果 G 走通**：
- 回到原 M5 路线完成 S5 评估 + 文档同步 (Phase 8)
- 记录"offline RL 在这个任务上需要 BC warm-start"作为 M5 的核心经验

### 6.3 为什么不建议先试 A/B/C/F

- **A/B** 是在同一个病根上试超参, Phase 11.7-C 已经试过多组无效
- **C (MC return shaping)** 虽然绕开了 TD 传播, 但把 episode return 分摊到每 tick 会**放大 reward 方差**, Q 学习更难
- **F (Rust 里加 signal-based shaping)** 工程量大 + 需要重采集 tick_stream, 而且**本质上是把 label 泄露进 reward**, 与 E 殊途同归但成本高 10 倍

### 6.4 为什么建议放弃"纯 offline RL"作为 M5 唯一范式

Phase 11.8-H 的诊断已经回答了"数据里有没有 alpha"（**有**），也回答了"M3 backbone 有没有 signal"（**有**）。从 m5_run2 到 m5_run5 一共 **5 次重训**都塌缩到 Hold, 这不是调参能解决的。

本任务的**结构性特征**（稀疏结算 reward + 1200 tick horizon + 噪声 dominated single-step reward）**先天不适合** offline RL。类似的任务在 literature 里的成功方案都是：
- **Sparse reward 任务 → reward shaping or reward relabeling**
- **Long horizon + 稀疏 reward → MC return 或 hierarchical**
- **小数据量 + 明确 expert → imitation / BC**
- **先 BC warm-start, 再 RL fine-tune**（AlphaStar、OpenAI Five 都是这条路）

我们手上有：
- **明确的 expert signal**：label_up（事后完美信息）
- **小数据量**：~2400 episodes
- **稀疏 reward**：大部分是噪声

**这组条件指向 BC + 可选的 RL fine-tune, 而不是 pure IQL**。

### 7.6 frozen split 口径 + full-range / `val` 说明

- frozen split 的来源：早期 M3 Run 1/2 曾因“各 parquet 自己切 train/val/test，再拼接”造成跨数据集时间泄漏；后续修正为**全局时间前推**，再把结果冻结到 `source://legacy/poly-arb-ai/training/checkpoints/m5_run_bc_diag/split_info.frozen.json`，供 `train_oracle_bc.py`、`train_iql.py`、`OracleBCDataset`、`TransitionDataset` 与 `agent evaluate --split-info` 统一复用。
- 当前 canonical split 组成：
  - `train=39` 个 window：`data-v1(2) + data-v2(20) + data-v3(17)`，时间到 `1775102400-1775116800`
  - `val=8` 个 window：全部来自更晚的 `data-v3`
  - `test=10` 个 window：全部来自最晚的 `data-v3`
- 三个 split 的职责：
  - `train`：拟合 Oracle BC / Hybrid BC→IQL 参数
  - `val`：选 checkpoint、阈值、执行配置，尽量避免拿 `test` 调参
  - `test`：最终 held-out 结论，只在路线确认时使用
- full-range 扫描（仍然沿用同一个 frozen split，只是把 `train/val/test` 都跑一遍）：
  - `signal@0.58 + limit`：`train=+3282.0262`、`val=-95.1558`、`test=+66.0951`、`full=+3252.9655`
  - `hold`：`train=+9.3774`、`val=+0.6233`、`test=-26.1318`、`full=-16.1311`
  - 因而 full-range 的净优势为 `+3269.0966`
- 这组 full-range 结果只能算**历史鲁棒性扫描**，不能替代 held-out 结论，因为它包含 `train/val`。
- `val` 8 窗口失效定位：
  - 离线 `signal_head` 并没有在 `val` 变差：`threshold=0.58` 时 `val_selected_accuracy=0.7091`、`val_auc=0.7542`，略高于 `test=0.7063 / 0.7415`
  - replay 市场级 hit/miss 才是问题：`val` 为 `145 / 145`，`avg_hit_pnl=+4.8003`、`avg_miss_pnl=-5.4566`；`test` 为 `174 / 162`，`avg_hit_pnl=+4.2347`、`avg_miss_pnl=-4.1404`
  - 结论：`val` 不是“没有信号”，而是该时间段 miss 的成本更重，属于非平稳 market-regime 风险；最差 miss 多出现在错误方向、入场价约 `0.55~0.63` 的市场，单笔可亏 `~8` 到 `9.45` USDC。
