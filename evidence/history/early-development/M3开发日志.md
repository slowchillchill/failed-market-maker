## 二、模型架构

### 列索引约定（与 dataloader.py FEATURE_COLS 对齐，固定）

| 分支 | 列索引 | 维度 |
|------|--------|------|
| PolymarketBranch（TCN） | 0–35 | 36 |
| BinanceBranch（TCN，Binance20+BLB3） | 36–58 | 23 |
| ChainlinkBranch（MLP） | 59–62 | 4 |
| 时间上下文（注入 Transformer） | 63–64 | 2 |

### InputNormalizer

- 非可学习 buffer（_mean, _std），随 checkpoint 保存/加载
- `set_stats(mean, std)` 在训练开始前由训练分区直接计算的 mean/std 初始化
- NaN（缺失值/零填充）归一化后映射到 0.0（特征均值）
- **NaN 处理**：使用 `torch.where(normed != normed, zeros_like, normed)` 处理缺失值（IEEE 754 NaN 特性），映射到归一化空间的 0.0（特征均值）

### 分支编码器

- **CausalTCN**：4 层因果膨胀卷积，dilation=[1,2,4,8]，kernel_size=4，仅左侧 pad
- **PolymarketBranch**：CausalTCN(36→64)
- **BinanceBranch**：CausalTCN(23→64)
- **ChainlinkBranch**：MLP(4→32→64)，per-timestep（Chainlink 约 1Hz，TCN 无必要）

### TinyCausalTransformer 融合层

- 输入：concat([poly, bin, cl], dim=-1) = (B, T, 192)，拼接时间上下文 → Linear(194, 128)
- 正弦位置编码（固定，不可学习）
- 2 层 TransformerEncoderLayer(d_model=128, nhead=4, dim_ff=256, pre-LN, batch_first=True)
- 上三角因果掩码 + `is_causal=True`

### SignalHead

- 输入：最后一个时间步状态 (B, 128)
- 共享 stem：Linear(128, 64) → ReLU
- 分类头：Linear(64, 2) → logits（不 softmax，交给 CrossEntropyLoss）
- EV 回归头：Linear(64, 2) → [ev_up_pred, ev_down_pred]

### 参数量

约 375K 参数（轻量），VRAM 峰值 < 500MB（batch_size=128, seq_len=240）。

## 三、损失函数（loss.py）

```
total = lambda_cls × CrossEntropyLoss(logits, y_cls) 
      + lambda_ev × masked_MSE(ev_pred, y_ev)
```

- `lambda_cls=1.0, lambda_ev=0.5`（默认）
- EV 损失仅对 `y_ev_mask=True` 的样本计算，避免 NaN 传播
- 返回 `(total, cls_loss.detach(), ev_loss.detach())`

## 四、评估指标（evaluate.py）

### 主判据（Phase 1 盈利代理）

| 指标 | 含义 | 要求 |
|------|------|------|
| `top_decile_mean_ev_up` | P_up 前 10% 样本的 mean(y_ev_up) | > 0 |
| `ev_up_sign_acc` | (ev_up_pred>0)==(y_ev_up>0) 的比例 | > 0.52 |

### 辅助指标（理智检查）

| 指标 | 含义 | 要求 |
|------|------|------|
| `auc` | roc_auc_score(y_cls, P_up) | > 0.52 |
| `brier` | mean((P_up - y_cls)²) | < 0.25 |
| `ece` | 期望校准误差（10 bins） | < 0.05 |
| `ev_rank_corr` | Spearman(ev_up_pred, y_ev_up) | > 0.03 |

### 诊断指标

- `ev_up_conditional_mean_by_threshold`：P_up > {0.50,0.52,0.55,0.60,0.65} 各阈值下 mean(y_ev_up)
- `ev_up_opportunity_rate_by_threshold`：各阈值下的样本占比
- `edge_by_decile`：按 P_up 分 10 分位，各组 mean(y_ev_up)；单调递增为佳

## 五、训练流程（train.py）

### CLI 参数

```bash
PYTHONPATH=poly-arb-ai python3 poly-arb-ai/training/train.py \
  --parquet-paths <path1> [<path2> ...] \
  --seq-len 240 \
  --batch-size 128 \
  --lr 1e-4 \
  --epochs 30 \
  --lambda-cls 1.0 \
  --lambda-ev 0.5 \
  --d-model 128 \
  --n-transformer-layers 2 \
  --dropout 0.1 \
  --output-dir /path/to/output \
  --device cuda \
  --num-workers 4
```

### 关键步骤

1. 加载所有 parquets → FeatureDataset（多路径合并）→ 全局 time_ordered_split（严格时间前推）
2. 从训练分区直接计算 per-feature mean/std，保存 feature_stats.npz
3. model.normalizer.set_stats(mean, std) 初始化归一化
4. 训练循环：AdamW + CosineAnnealingLR，tqdm batch 进度条
5. 最优 checkpoint 按 val top_decile_mean_ev_up 保存（best_model.pt，torch.compile 时自动去除 `_orig_mod.` 前缀）
6. 最终在 test split 上 compute_metrics，打印 Phase 1 pass/fail

### 输出文件

```
output-dir/
├── best_model.pt          # 最佳模型权重 + optimizer + val_metrics + args
├── feature_stats.npz      # mean, std, feature_cols（用于推理端复现归一化）
├── test_metrics.json      # 最终 test set 指标
└── train_history.json     # 所有 epoch 指标历史
```

| 问题 | 原因 | 修复 |
|------|------|------|

### 过拟合根本原因分析

三轮训练均出现同一规律：**best checkpoint 始终是第 1 epoch**，与超参数和切分方式无关。

根本原因：**时间分布漂移（temporal non-stationarity）**。训练/验证/测试按时间顺序切分（70%/15%/15%），模型训练越久，越记忆旧时间段特有的市场微结构模式；这些模式在新时间段（val/test）中不成立，导致 val_loss 持续上升。这是金融时序预测的固有问题，不是代码缺陷。

ECE=0.1900 偏高也源于此：模型在训练集上过度自信的概率估计，在分布不同的 test 集上变得不准确。

### GPU 加速关键发现

| 配置 | GPU 利用率 | epoch 时间 |
|------|-----------|-----------|
| batch=128（初始） | **10%** | ~7 分钟 |
| batch=2048（优化后） | **92%** | **~61 秒** |

RTX 5090 有 32GB VRAM，batch=128 时模型只占 1.1GB，GPU 处于饥饿状态。扩大 batch 至 2048 后 VRAM 占用 7-9GB，GPU 利用率达到 92%，**整体吞吐量提升 9x**。

**AMP bfloat16 eval bug（已修复）：** 开启 `--amp` 时，eval_epoch 中 logits/ev_pred 为 bfloat16，直接 `.cpu().numpy()` 报 `TypeError: Got unsupported ScalarType BFloat16`。修复方法：加 `.float()` 再 `.numpy()`。

### 新增 train.py 功能（本次训练过程中完善）

- FeatureDataset 多路径合并：支持传入路径列表，全局时间排序切分，确保严格时间前推
- torch.compile checkpoint 兼容：保存时自动去除 `_orig_mod.` 前缀
- `--patience N`：早停参数，val top10_ev 连续 N epoch 不提升则停止（0=禁用）
- `persistent_workers=True` + `prefetch_factor=4`：DataLoader 预取优化
- `--amp`：bfloat16 自动混合精度（CUDA only）
- `--compile`：torch.compile 内核融合（首 batch 编译约 14s，后续加速）
